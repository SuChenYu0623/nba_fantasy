# NBA Fantasy 輔助擴充功能 — UI 重做與輸出精簡 設計文件

日期：2026-10-22
狀態：待審查

## 1. 背景與動機（Why）

這是一個 Manifest V3 Chrome 擴充功能，掛在 Yahoo Fantasy 籃球聯盟頁
（`https://basketball.fantasysports.yahoo.com/*`）。使用者在頁面右上角的
小面板輸入「week」送出後，擴充功能會爬取該週各隊的分類數據，做 min-max
正規化評分與排名，並開出兩個新分頁：一張**結果表格**、一張**雷達圖**。

目前三個畫面（小面板、表格頁、雷達圖頁）都「太陽春、不夠現代化」，且：

- 表格欄位爆炸：每個項目同時顯示原始值 + 正規化分數（`_score`）+ 名次，
  11 個項目造成 30+ 欄，又寬又雜。
- 雷達圖一次疊上全部 12 隊，要比較得靠 Chart.js 預設圖例**逐隊手動點掉**，
  UX 很差。

使用者要的是把三個畫面重做成現代化風格，並順手精簡輸出。

## 2. 目標（Goals）

- 三個畫面統一採用**「極簡亮白」視覺語言**（見 §4.1），看起來現代、乾淨。
- **表格精簡**：只顯示「原始數據 + 各項小名次 + 總分 Total + 排名」，
  **隱藏所有 `_score` 欄**（分數仍在背後計算，供雷達圖使用）。
- **雷達圖改為「聚焦 + 比較」互動**：預設只聚焦單一隊伍，使用者可再加入
  1–2 隊疊著比較，其餘隱藏；不再需要手動關掉一堆圖例。
- 在改版過程順手做一處程式整理：把重複寫了三份的 metrics 清單收斂為
  單一共用常數。

## 3. 非目標 / 反目標（Non-goals / Anti-goals）

- **不**導入前端框架或打包工具（React、Vite 等）。維持現有的「無 build、
  原生 JS/CSS、透過 content script 注入、輸出頁以 HTML 字串 + Blob URL
  開啟」的做法。
- **不**做深色模式切換（視覺方向 A 為亮色；深色留待日後若有需求）。
- **不**更動爬蟲 / 聯盟 id / 動態隊數邏輯（上一輪已完成）。
- **不**加入設定儲存、帳號、後端等新機制。
- 反目標：表格不可為了「乾淨」而拿掉使用者倚賴的**各項小名次**；精簡的是
  `_score` 欄，不是名次資訊。

## 4. 已決定的設計（How，已和使用者確認）

### 4.1 視覺語言：極簡亮白（方向 A）

- 底色淺灰（如 `#f6f7f9`）、內容為白色卡片、圓角（約 12–16px）、柔和陰影。
- 單一強調色：靛藍 `#6366f1`（可微調）。大量留白。
- 數字使用等寬數字（`font-variant-numeric: tabular-nums`）。
- 表格列用極淡的 zebra 分隔。
- 字體沿用現有 system-ui / Noto Sans TC 堆疊。

此語言同時套用到：小面板、表格頁、雷達圖頁，三者視覺一致。

### 4.2 小面板（右上角注入的 overlay）

- 維持現有能力：Shadow DOM 隔離、可拖曳、關閉鈕、week 輸入、送出、進度條。
- 以 A 風格重做外觀：白色圓角卡片、標題列含強調色小圓點 + 標題、藥丸狀
  輸入框、靛藍送出鈕、較精緻的進度條。
- 送出流程、進度回報邏輯不變（總數由當週對戰組數動態決定）。

### 4.3 表格頁

- A 風格：白色卡片容器、sticky 表頭、淡 zebra、Team 欄 sticky 置左。
- 欄位＝ **排名(Rank) · Team · 11 個項目的原始值（各帶該項小名次）·
  總分 Total**。`Rank` 以靛藍底色小徽章呈現；`Total` 以粗體數字搭配
  一條迷你比例條。
- **隱藏 `_score` 欄**（不再輸出到表格）。
- 保留點表頭排序的互動。
- 寬度仍可能超出視窗 → 保留水平捲動；在手機寬度可用。

### 4.4 雷達圖頁：聚焦 + 比較

- 以 Chart.js（本地 `chart.umd.min.js`）繪製，沿用 11 項分類。
- 互動：
  - 一個「主隊」選擇器（聚焦，實心高亮填色）。
  - 「加入比較」可再選最多 2 隊（以外框／虛線呈現，不同顏色）。
  - 未選取的隊伍一律**隱藏**（而非畫出後讓使用者手動關）。
  - 切換選擇時以程式重建 datasets，不依賴 Chart.js 預設圖例點選。
- A 風格：淺色格線、靛藍系填色。
- 使用背後算好的 `_score` 值作為雷達數據（0–100）。

### 4.5 計算流程整理

- 計算邏輯（min-max 正規化 → Total 平均 → 排名）維持不變。
- 將 metrics 清單（目前在評分、雷達資料 mapping、雷達 labels 各寫一份）
  收斂為**單一共用常數**（含 reverse 項，如 `TO`），三處共用。
- `_score` 仍照算（雷達需要），只是不攤進表格。

## 5. 限制（Constraints）

- Manifest V3、無 build step、原生 JS/CSS。
- 輸出頁沿用「content.js 內以字串組出 HTML → Blob URL 開新分頁」機制；
  注入的面板沿用 Shadow DOM。
- 跨分頁無法共用 runtime 狀態；每次送出重新產生頁面。
- 擴充功能靠瀏覽器既有 Yahoo 登入 session 抓資料，前端無任何憑證。

## 6. 留給 builder 決定的細節

- 各畫面精確的間距 / padding / 陰影數值（在 A 風格範圍內）。
- 雷達圖「主隊 / 加入比較」控制元件的具體形式（原生 `<select>`、晶片、
  或下拉搜尋）與預設聚焦哪一隊（例：預設聚焦 Rank 1）。
- 表格 Total 迷你比例條的縮放方式、小名次的呈現樣式（括號 / 上標 / 角標）。
- 進度條動畫細節、送出鈕 hover/active 回饋。
- metrics 共用常數擺放的位置與命名。
- 是否把 content.js 內過大的區塊（UI / 爬蟲 / 計算 / 產頁）順手切分為較小
  的函式群組，只要不引入 build step 即可。

## 7. 成功樣貌

使用者送出 week 後，看到的小面板、表格、雷達圖三者風格一致、乾淨現代；
表格一眼可讀（原始數據 + 名次 + 總分排名，不再被分數欄淹沒）；雷達圖打開
即聚焦單隊，想比較誰就加誰，不必手動關掉一堆線。
