# 正規化升級 v2：跨週可比戰力值 設計文件

日期：2026-10-22
狀態：待審查

## 1. 背景與動機（Why）

目前每項數據用「當週 N 隊之間的 min-max」映射到 20–100，等權平均成 Total。
這有兩個專業上的弱點：(1) min-max 被當週最高/最低兩隊綁架，單一離群值扭曲整欄；
(2) 比率項（FG%/FT%/3PT%）沒考慮出手量，小樣本高命中被高估。

更關鍵的是：使用者要的是「**Total 是有意義、可跨週比較的戰力值**」。而任何「只用當週
族群」的正規化（含 z-score）每週都會重新置中在 0，本質上只相對當週對手，**給不出跨週
可比性**。要跨週可比，必須有一把跨週固定的量尺。

本次升級改用業界（fantasy 籃球圈）常見的 **volume-weighted robust z-score**，並以
**持久化的滾動歷史基準**當量尺，讓 Total 成為跨週可比的戰力值。

## 2. 目標（Goals）

- **Total ＝ 跨週可比的戰力值**：0 ≈ 歷史基準上的「平均隊」，正值高於平均。
- 比率項（FG%、FT%、3PT%）以**出手量加權**（volume-weighted）。
- 以 **robust 標準化（中位數 / MAD）** 對一把**持久化、per-league 的滾動基準**衡量。
- 基準自我校準：每跑一週就把該週統計累積進基準；換季（leagueId 改變）自動開新基準。
- 表格外觀與雷達互動維持 v1 既有設計；標準化值仍隱藏，只餵 Total 與雷達。

## 3. 非目標 / 反目標（Non-goals / Anti-goals）

- **不**引入後端/伺服器；持久化僅用 `chrome.storage.local`。
- **不**用人工寫死的常數當量尺（量尺來自累積資料，非 hardcode）。
- **不**顯示出手量欄（FGM/A 等）；僅在背後用於計算。
- **不**更動既有爬取流程、UI 版型（A 風格）、雷達「聚焦+比較」互動、表格欄位組成。
- **不**跨聯盟共用基準。
- 反目標：第 1 週 bootstrap 的數字不得偽裝成已校準的跨週值 —— 需有「校準中」提示。
- 反目標：把純計算邏輯綁進 `chrome.*` API，破壞 Node 可測性。

## 4. 已決定的設計（How，已與使用者確認）

### 4.1 標準化方法

對每一項、對基準量尺做：

- **計數項**（PTS、REB、AST、ST、BLK、3PTM、DD）與 **TO**：
  `score = (隊值 − 基準中位數) / 基準MAD`；**TO 取負**（越少越好）。
- **比率項**（FG%、FT%、3PT%）：先算出手量加權影響值
  `impact = (隊比率 − 基準聯盟比率) × 該隊出手量`，再對 impact 做
  `score = (impact − 基準impact中位數) / 基準impactMAD`。
- **Total ＝ 11 項 score 加總**。0 ≈ 平均、正為高於平均。

出手量來自既有爬取結果中的 `FGM/A*`、`FTM/A*`、`3PTA*` 欄（key 可能帶 `*`）：
由 `FGM/A`→FGA、`FTM/A`→FTA、`3PTA`→3PTA 解析（「45/90」取分母為出手量）。
這些欄位**已經被抓進 item 物件**，只是不顯示，不需改爬蟲。

### 4.2 持久化滾動基準（量尺）

- 存於 `chrome.storage.local`，**以 leagueId 為 key**；換季聯盟 id 改變即自動開新基準。
- 基準以「**pooled 樣本**」保存：每項保留跨週累積的 per-team 值（比率項另需 makes/attempts
  以還原聯盟比率與 impact），用以計算中位數 / MAD / 聯盟比率。樣本量上限（例如最近 K 週，
  K 由 builder 定，建議約 20 週）以限制儲存大小。
- **更新規則**：每跑完一週，把該週 per-team 值併入 pool、裁到上限、存回（cumulative）。
- **Bootstrap（第 1 週 / 該聯盟無基準）**：以當週各隊作為初始 pool（該次等同當週自我相對），
  存入後往後逐週校準。

### 4.3 呈現

- 表格外觀不變（Rank · Team · 11 項原始值+當週小名次 · Total）。小名次仍以「當週」標準化值
  排序。標準化值本身隱藏。
- **Total 顯示為加總後的數值（約 1 位小數）**，不再是 20–100；0＝平均。
- 雷達圖沿用「聚焦+比較」，數據改用標準化值，軸以 0 為中心（範圍依資料動態，如 −3…+3）。
- **校準提示**：顯示「基準校準中：已累積 N 週」之類文字（面板或表格頁），讓早期數字的
  可比性狀態透明。

### 4.4 架構（維持可測性）

- 純數學留在 `lib/stats.js`：新增**吃 baseline 參數、回傳標準化結果**的純函式，以及
  **由一週資料更新 baseline** 的純函式。皆可用 `node --test` 測，不碰 `chrome.*`。
- `chrome.storage` 的讀/寫只在 `content.js`（瀏覽器端）：送出時先載入該 league 的 baseline
  → 傳入純函式算分 → 顯示 → 把本週併入 baseline 存回。
- `content.js` 送出流程本來就是 async，容納 storage I/O。

## 5. 限制（Constraints）

- MV3、無 build step、原生 JS/CSS；lib 以 dual-env 模組 + `node --test`。
- `chrome.storage.local` 為非同步；`storage` 權限 manifest 已具備。
- 每次執行 = 一週、一聯盟。
- MAD 可能為 0（過半隊同值）→ 需防除以 0。

## 6. 留給 builder 決定的細節

- baseline 的確切資料結構與 pool 上限 K（建議 ~20 週）。
- MAD＝0 時的退路（建議：該項該隊 score 記 0，即視為等於基準中心）。
- 無法解析出手量 / 缺值時的處理（建議：該項 score 以 0＝中性計，而非舊版的「最差」；
  此為相對 v1 的行為變更，請審閱）。
- 「校準中」提示的確切文字、位置與何時淡出（例如累積 ≥3 週後不再顯示）。
- 雷達軸的實際範圍與刻度。
- Total 顯示的小數位與是否加正負號。
- 純函式的命名與擺位（延續 `NbaStats`）。

## 7. 成功樣貌

使用者連續幾週使用後，同一隊的 Total 能反映「相對聯盟歷史平均的戰力」且跨週可比；
比率項不再被低出手量灌水；離群值不再壓扁整欄；表格與雷達外觀一如 v1，只是數字更可信，
並清楚標示基準仍在校準的早期階段。
